1. 개요

1.1 프로젝트 배경

본 문서는 정서샤워(Emotional Shower) 모바일 앱 MVP 개발 프로젝트의 데이터베이스 스키마 설계서입니다. 정서샤워는 정서적 위생과 30일 친절 챌린지를 중심으로 한 모바일 우선 웹 애플리케이션으로, 사용자들의 감정 체크인, AI 대화, 커뮤니티 기능, 코호트 기반 참여 추적을 제공합니다.

데이터베이스는 Supabase(PostgreSQL 15.x 기반)를 사용하며, 행 단위 보안(Row Level Security)을 통해 사용자 데이터를 안전하게 보호합니다. 2025년 11월 25일 초기 스키마가 구축되었으며, 11월 30일 이미지 스토리지 기능이 추가되어 현재 v1.1 버전으로 운영 중입니다.

3. 테이블 상세 명세

3.1 users (사용자 프로필)

Supabase Auth와 연동된 사용자 프로필 정보를 저장합니다.

표 3-1. users 테이블 컬럼 명세
No 컬럼명 데이터 타입 NULL 키 설명
1 id PK UUID N PK, FK Supabase Auth 사용자 ID (auth.users 참조)
2 name TEXT N - 사용자 이름
3 email UNIQUE TEXT N UNIQUE 이메일 주소
4 current_cohort_id FK UUID Y FK 현재 참여 중인 기수 ID (cohorts 참조)
5 is_admin BOOLEAN N - 관리자 여부 (기본값: false)
6 created_at TIMESTAMPTZ N - 생성 일시
7 updated_at TIMESTAMPTZ N - 수정 일시 (트리거 자동 업데이트)

RLS 정책

  • SELECT: 사용자는 본인 데이터만 조회 가능 (auth.uid() = id)
  • INSERT: 사용자는 본인 프로필 생성 가능 (auth.uid() = id)
  • UPDATE: 사용자는 본인 데이터만 수정 가능 (auth.uid() = id)

3.2 cohorts (기수 정보)

챌린지 기수(코호트) 정보를 관리합니다.

표 3-2. cohorts 테이블 컬럼 명세
No 컬럼명 데이터 타입 NULL 키 설명
1 id PK UUID N PK 기수 고유 ID
2 name TEXT N - 기수명 (예: "2024년 1기")
3 start_date DATE N - 시작일
4 end_date DATE N - 종료일
5 description TEXT Y - 기수 설명
6 status cohort_status N - 기수 상태 (recruiting/active/completed)
7 record_type record_type_enum N - 기록 유형 (both/self_care_only/kindness_only)
8 max_participants INTEGER Y - 최대 참여 인원
9 created_at TIMESTAMPTZ N - 생성 일시
10 updated_at TIMESTAMPTZ N - 수정 일시

RLS 정책

  • SELECT: 모든 인증된 사용자가 조회 가능
  • INSERT/UPDATE/DELETE: 관리자만 가능 (is_admin = true)

3.3 user_cohorts (사용자-기수 참여)

사용자와 기수 간의 다대다(N:M) 관계를 저장하는 중간 테이블입니다.

표 3-3. user_cohorts 테이블 컬럼 명세
No 컬럼명 데이터 타입 NULL 키 설명
1 id PK UUID N PK 레코드 고유 ID
2 user_id FK UUID N FK 사용자 ID (users 참조)
3 cohort_id FK UUID N FK 기수 ID (cohorts 참조)
4 joined_at TIMESTAMPTZ N - 참여 일시
5 completed_at TIMESTAMPTZ Y - 완료 일시
6 status participation_status N - 참여 상태 (active/completed/failed)

제약조건

  • UNIQUE: (user_id, cohort_id) - 사용자당 기수별 1개 참여만 허용

RLS 정책

  • SELECT: 사용자는 본인의 참여 이력만 조회 (auth.uid() = user_id)
  • INSERT: 사용자는 본인의 참여만 생성 (auth.uid() = user_id)

3.4 challenges (챌린지 진행)

사용자별, 기수별 30일 챌린지 진행 상태를 저장합니다.

표 3-4. challenges 테이블 컬럼 명세

일일 자기돌봄 및 타인친절 행동 기록을 저장합니다. 이미지 첨부 기능 지원 (v1.1 추가)

표 3-5. daily_records 테이블 컬럼 명세

3 cohort_id FK UUID N FK 기수 ID (cohorts 참조)

  • UPDATE: 관리자만 상태 변경 (is_admin = true)

4. 보안 및 데이터 무결성

4.1 Row Level Security (RLS) 정책 요약

모든 테이블에 RLS(행 단위 보안)가 적용되어 있으며, Supabase Auth의 JWT 토큰을 통해 사용자 인증 및 권한을 자동으로 검증합니다. 총 30개의 RLS 정책이 적용되어 있습니다.

표 4-1. 테이블별 RLS 정책 매트릭스
테이블 SELECT INSERT UPDATE DELETE Admin 권한
users 본인 본인 본인 - -
cohorts 전체 - - - 전체
user_cohorts 본인 본인 - - -
challenges 본인 본인 본인 - -
daily_records 본인 본인 본인 - 전체 조회
surveys 본인 본인 - - 전체 조회
community_posts 같은 기수 본인 본인 본인 전체 조회
community_comments 접근 가능 게시글 본인 - 본인 전체 조회
applications 코드 검증(public) 누구나 - - 전체
